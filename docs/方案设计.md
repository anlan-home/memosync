# 家庭备忘录（家庭版）整体方案设计

> 定位：自托管的家庭备忘录系统 —— Android 客户端（离线优先）+ NAS 服务端（FPK 一键安装），数据 100% 存在自己家里。
> 用户规模：2~10 名家庭成员，单台 NAS，无高并发压力。

---

## 0. 三条设计原则

1. **离线优先**：没网也能看、能记、能改，联网后自动同步。NAS 挂了手机本地数据不丢。
2. **数据自有**：所有数据存 NAS，格式开放（SQLite + 原始附件文件），随时可备份、可导出、可迁移。
3. **长辈友好**：大字号、界面简单、提醒可靠（家人里可能有长辈，这是家庭场景和普通笔记软件最大的差异点）。

---

## 1. 总体架构

```
┌──────────────────┐                        ┌─────────────────────────────┐
│   Android App    │      HTTPS (REST)      │        NAS (fnOS)           │
│                  │ ◄────────────────────► │                             │
│  Kotlin/Compose  │   ①登录换 token        │  ┌───────────────────────┐  │
│  Room 本地库     │   ②push 本地变更       │  │  MemoSync 服务 (FPK)   │  │
│  WorkManager     │   ③pull 增量变更       │  │  Go 单二进制 + SQLite   │  │
│  (后台同步/提醒)  │   ④附件上传/下载       │  └──────────┬────────────┘  │
│                  │                        │  /vol1/memosync/data/       │
└──────────────────┘                        │   ├─ memo.db   (SQLite)     │
                                            │   ├─ attachments/ (图片等)   │
        离线可用：UI 只读本地库              │   └─ backup/   (每日自动)    │
        同步只发生在后台                     └─────────────────────────────┘
```

- **客户端是本地数据库的单向使用者**：UI 永远只读 Room，写操作也先落 Room（打 dirty 标记），同步器再把它推到 NAS、把 NAS 的增量写回 Room。这是离线优先的标准做法，网络抖动不影响任何 UI 操作。
- **服务端是权威同步中心**：不做实时协同编辑，只做"变更集"的可靠中转，家庭场景下复杂度低、可靠性高。

## 2. 技术选型

| 端 | 选型 | 理由 | 备选 |
|---|---|---|---|
| NAS 服务端 | **Go 1.22+ 单二进制 + SQLite**（modernc.org/sqlite，纯 Go 无 CGO） | 交叉编译 amd64/arm64 一条命令；内存占用 < 30MB；零运行时依赖，最适合打成 FPK | Node.js (Fastify)、Python (FastAPI)——都需带运行时，包体积和内存更大 |
| 服务端 API | REST + JSON（kotlinx.serialization / encoding/json） | 简单、调试方便，家庭规模 REST 足够 | gRPC（过重） |
| 实时性 | MVP：30s 轮询 + 事件触发；V2：SSE 推送 | 家庭场景"秒级同步"非刚需 | WebSocket |
| Android 客户端 | **Kotlin + Jetpack Compose + Material 3** | 现代声明式 UI，Google 官方主推，卡片流/瀑布流实现成本低 | 传统 View 体系（不再推荐） |
| 本地存储 | Room（SQLite） | 单一事实源，Flow 响应式刷新 | SQLDelight |
| 网络 | Retrofit + OkHttp | 生态成熟 | Ktor Client |
| 后台任务 | WorkManager（同步）+ AlarmManager/精确闹钟（提醒） | 系统级约束调度，省电且兼容各家 ROM | — |
| 配置存储 | DataStore | 官方推荐，替代 SharedPreferences | — |
| 最低版本 | minSdk 26（Android 8.0） | 覆盖家人全部手机，避开旧版兼容坑 | minSdk 24 |

> **快速验证捷径（备选路线）**：若想先"用起来"，可在 NAS 的 Docker 里一键跑开源的 [Memos](https://github.com/usememos/memos)（或 Joplin Server + Joplin App），手机浏览器即可使用。自研的价值在于：家庭共享模型、可靠提醒、离线优先、长辈模式、产品化 FPK 打包。建议以本方案自研为主线，Docker 版作为过渡或兜底。

## 3. 核心概念与数据模型

### 3.1 核心概念

- **空间 Space**：`个人空间`（仅自己可见）/ `家庭空间`（全员可读写）。每条备忘录归属一个空间，首页可按空间筛选。
- **备忘录 Memo**：三种形态统一在一张表（content 为客户端定义的 JSON，服务端不解析结构）：
  - `note` 文本笔记（标题 + 富文本正文，MVP 支持加粗/清单/待办勾选）
  - `checklist` 清单（条目数组，可勾选）
  - `asset` **数字资产**（家庭账号密码托管）：
    ```json
    {"type":"asset","category":"video","account":"13800138000","password":"…",
     "extra":"妈妈开的，已关自动续费","expires_at":1798761600000,"remind_before":7}
    ```
    - `title` 即资产名称（如「爱奇艺黄金VIP」），提醒通知直接用它
    - `expires_at` 到期日（本地当日 0 点），卡片显示倒计时（剩余 N 天 / 今天到期 / 已过期，≤7 天标红）
    - `remind_before` 提前提醒天数（-1 不提醒 / 0 当天 / 3 / 7 / 30），服务端 `remind_at = 到期日 09:00 − N 天`，完全复用现有精确闹钟提醒链路
    - 账号/密码一键复制、密码默认遮蔽可切换显示；放家庭空间=全家可见，放个人空间=仅自己
    - 安全边界：密码**明文同步至自家 NAS**（家庭共享场景的取舍），外网访问务必走 Tailscale/HTTPS
- **附件 Attachment**：图片为主，只增不改（不可变对象，天然无冲突）。
- **软删除 tombstone**：删除先进两端回收站，30 天后服务端物理清理，防误删防丢数据。

### 3.2 服务端 SQLite 表结构（DDL 摘要）

```sql
CREATE TABLE users (
  id            TEXT PRIMARY KEY,            -- uuid
  username      TEXT UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,               -- argon2id
  nickname      TEXT NOT NULL,
  role          TEXT NOT NULL DEFAULT 'member',   -- admin / member
  created_at    INTEGER NOT NULL
);

CREATE TABLE spaces (
  id   TEXT PRIMARY KEY,
  name TEXT NOT NULL,                        -- "家庭共享" / "某某的私人空间"
  type TEXT NOT NULL                         -- family / personal
);

CREATE TABLE memos (
  id          TEXT PRIMARY KEY,              -- 客户端生成 uuid，避免分配冲突
  creator_id  TEXT NOT NULL,
  space_id    TEXT NOT NULL,
  type        TEXT NOT NULL DEFAULT 'note',  -- note / checklist
  title       TEXT DEFAULT '',
  content     TEXT DEFAULT '{}',             -- JSON：富文本/清单条目，统一存 JSON
  color       TEXT DEFAULT 'default',
  pinned      INTEGER DEFAULT 0,
  archived    INTEGER DEFAULT 0,
  remind_at   INTEGER,                       -- Unix 毫秒，NULL=无提醒
  created_at  INTEGER NOT NULL,
  updated_at  INTEGER NOT NULL,              -- 服务端权威时间
  client_mtime INTEGER NOT NULL,             -- 客户端修改时间（LWW 用）
  deleted_at  INTEGER,                       -- 软删除
  version     INTEGER NOT NULL DEFAULT 1     -- 服务端每次接受写入 +1（乐观锁）
);

CREATE TABLE attachments (
  id       TEXT PRIMARY KEY,
  memo_id  TEXT NOT NULL,
  sha256   TEXT UNIQUE NOT NULL,             -- 内容寻址，全局去重/秒传
  filename TEXT NOT NULL,
  mime     TEXT NOT NULL,
  size     INTEGER NOT NULL
);

-- 同步游标来源：任何一次 memo 写入（含删除）都追加一行，seq 单调递增
CREATE TABLE changes (
  seq      INTEGER PRIMARY KEY AUTOINCREMENT,
  memo_id  TEXT NOT NULL,
  deleted  INTEGER NOT NULL DEFAULT 0,
  at       INTEGER NOT NULL
);
```

## 4. 同步协议设计（核心）

### 4.1 设计原则

- **离线优先 + 服务端权威**：本地随时可写，服务端以 `version`（乐观锁）为一致性基准。
- **冲突处理分级**：
  - 文本笔记/资产：备忘录级 LWW + 冲突副本（被覆盖一方自动保全进回收站）
  - **清单：条目级合并**——双方都是清单时，服务端把过期基线的推送与当前版本做条目并集（服务端顺序为骨架，客户端独有条目追加，勾选状态取"或"，条目只增不减），合并成功直接接受，**不产生冲突副本**；无法安全合并（类型变更/内容非法）才回退冲突流程
- **标签**：`memos.tags` 列（JSON 数组，服务端清洗：去空、去重、≤10 个、单个 ≤24 字）；标签是客户端权威字段，推送须携带全量（旧客户端不带会清空，与 content 同语义）；pull 条目携带备忘录**当前**状态（changes 表不存历史快照）
- **增量拉取用单调游标**：客户端只记一个 `last_seq`，服务端 `changes` 表保证不漏不多。

### 4.2 同步流程

```
客户端                                    服务端
  │ 本地写 Room (dirty=1)，防抖 3~5s         │
  │──────── POST /sync/push ──────────────►│ 逐条校验 base_version：
  │  body: dirty memos + base_version       │   匹配   → 接受，version+1，写 changes
  │                                         │   不匹配 → 该条返回 conflict + 服务端版本
  │◄─────── results[] ─────────────────────│
  │ 冲突条目：比较后取服务端版本，本地版本    │
  │ 另存冲突副本(回收站)，通知栏提示          │
  │                                         │
  │──────── GET /sync/pull?since=seq ─────►│ 按 changes.seq 增量返回
  │◄─────── changes + latest_seq ──────────│ 写回 Room，更新 last_seq
  │ 附件：pull 先落元数据，Worker 按需下载； │
  │ push 前 POST /attachments（sha256 秒传）│
```

### 4.3 触发时机

| 时机 | 方式 |
|---|---|
| **SSE 实时推送（首选）** | 客户端保持 `GET /api/v1/sync/events` 长连接，任何成员变更提交后服务端立即广播 `event: change`，客户端毫秒级触发 pull；断线指数退避重连（1s→60s），25s 心跳保活 |
| App 启动 / 回前台 | 立即同步 |
| 本地有未推送变更 | 防抖 3~5 秒后推送 |
| 定时兜底 | WorkManager 每 30 分钟（有网约束），SSE 不可用（如国产 ROM 杀后台）时保证最终一致 |
| 用户下拉刷新 | 手动触发，UI 显示同步中 |

### 4.4 删除与清理

- 删除 = `deleted_at` 打标 + push；对端 pull 后同样进回收站。
- 服务端每日任务：物理清除 `deleted_at` 超过 30 天的记录与孤儿附件。

## 5. NAS 服务端详细设计（FPK 内的服务）

### 5.1 进程与模块

```
memosync/                     # Go 单 module
├── cmd/memosync/main.go      # 入口：配置加载、路由、优雅停机
├── internal/api/             # REST 处理器 + 中间件(token校验/日志)
├── internal/store/           # SQLite 访问层
├── internal/sync/            # push/pull/冲突/changes 追加
├── internal/attach/          # 附件存储(内容寻址: attachments/ab/cd/<sha256>)
├── internal/admin/           # 管理端 API + 内嵌静态管理页(web/, go:embed)
├── internal/backup/          # 每日备份(VACUUM INTO + 附件硬链接/rsync)
└── conf/config.yaml          # 端口 5231、数据目录(fnOS 安装时注入)
```

### 5.2 API 明细（v1）

| 方法 & 路径 | 说明 |
|---|---|
| `POST /api/v1/auth/login` | 账号密码 → `{token, user}`（长期 token，可管理端踢下线） |
| `GET /api/v1/auth/me` | 当前用户信息 |
| `GET /api/v1/spaces` | 我的空间列表（个人 + 家庭） |
| `POST /api/v1/sync/push` | 上传变更：`{memos:[{...本地 memo, base_version}]}` → 每条返回 `ok / conflict(+服务端 memo)` |
| `GET /api/v1/sync/pull?since=&limit=` | 增量拉取：`{changes:[{seq, memo, attachments}], latest_seq}` |
| `POST /api/v1/attachments/check` | 按 sha256 批量查询已存在（秒传） |
| `POST /api/v1/attachments` | multipart 上传，返回 id/sha256 |
| `GET /api/v1/attachments/{id}` | 下载（支持 If-None-Match 缓存） |
| `GET /api/v1/pair-code` | 管理端：生成一次性配对二维码（含 NAS 地址+凭证，家人手机扫码即完成配置） |
| `POST /api/v1/admin/users` 等 | 成员管理、存储用量、手动备份、全量导出（JSON + 附件 zip） |

### 5.3 管理页（服务端内嵌 Web，浏览器打开 :5231）

- 成员管理：创建/删除家庭成员账号、重置密码、设备列表与下线
- 存储用量、手动备份按钮、一键导出全部数据
- 生成"配对二维码"供家人手机扫码接入

### 5.4 备份与恢复

- **备份**：每日 02:00 `VACUUM INTO` 出 SQLite 快照 + 附件目录硬链接到 `backup/`，保留最近 7 份；管理页可手动备份。
- **恢复**（管理页 → 备份列表 → 恢复按钮）：两步走避免热替换——
  1. `POST /api/v1/admin/restore {name, confirm:true}`：校验备份 → 复制为 `memo.db.restore-pending` + 写恢复标记 + 备份中的附件 blob 立即补齐到附件目录
  2. **重启服务生效**：启动时检测到恢复标记 → 替换主库（清理旧 WAL/SHM）→ 日志记录
- 管理页可一键全量导出 zip（memos.json + 全部附件）。

## 6. FPK 打包方案（fnOS）

### 6.1 包结构（以飞牛开发者平台最新规范为准，字段名以官方文档为准）

```
memosync.fpk
├── manifest.json        # 包标识、版本、名称/图标、支持架构(amd64/arm64)、监听端口、数据目录声明
├── icon.png
├── bin/
│   ├── memosync_linux_amd64
│   └── memosync_linux_arm64      # 安装脚本按 NAS 架构择一启用
├── web/                 # 管理页静态资源（也被编译进二进制的则省略）
├── conf/config.yaml     # 默认配置；数据目录、端口由安装器注入
└── scripts/
    ├── pre-install.sh   # 检查架构/端口占用
    ├── post-install.sh  # 创建数据目录、生成首次管理员密码(打印到安装结果页)
    ├── start.sh         # 启动二进制（fnOS 托管，开机自启、崩溃拉起）
    ├── stop.sh
    └── pre-uninstall.sh # 停服务；数据目录保留（卸载不删数据）
```

### 6.2 安装后的行为设计

- 应用中心/手动上传 FPK 安装 → 自动起服务，桌面出现"家庭备忘录"图标（指向管理页）
- 首次打开管理页：设置管理员密码 → 创建家人账号或直接生成"扫码接入"二维码
- **升级 = 覆盖安装**：数据目录独立于包目录，升级只替换二进制，数据不动
- **卸载不删数据**，重装自动找回

### 6.3 外网访问（不在家也能用）

推荐顺序：
1. **Tailscale/WireGuard 组网（最推荐）**：NAS 和家人手机各装一个，免公网、免端口暴露、端到端加密，客户端 NAS 地址填 Tailscale IP 即可；
2. fnOS 自带 DDNS + HTTPS 反向代理（有公网 IP 时）；
3. 仅家庭局域网使用（同步只在在家时发生，客户端离线优先所以完全可用）。

## 7. Android 客户端设计

### 7.1 工程结构

```
app/src/main/java/com/family/memo/
├── data/
│   ├── local/      # Room: MemoEntity, MemoDao, ChecklistItem 转换
│   ├── remote/     # Retrofit: MemoApi, Dto, TokenInterceptor
│   ├── sync/       # SyncManager(编排 push/pull), SyncWorker, ConflictResolver
│   └── repo/       # MemoRepository —— UI 唯一数据入口
├── ui/
│   ├── list/       # 首页瀑布流
│   ├── editor/     # 编辑页(笔记/清单两形态)
│   ├── family/     # 家庭共享页
│   ├── remind/     # 提醒列表
│   ├── settings/   # 设置
│   └── auth/       # 登录 / 扫码接入
├── notify/         # 提醒调度: 精确闹钟 + RebootReceiver + 通知渠道
└── core/           # 主题、大字号、工具
```

### 7.2 离线优先实现要点

- Room 是**单一事实源**：UI 订阅 `dao.observeMemos(): Flow<List<...>>`，网络状态不影响 UI。
- 本地表带同步字段：`dirty`(待推送)、`base_version`(上次同步版本)、`local_only`。
- `SyncWorker`：push dirty → 处理冲突 → pull 增量 → 下载缺失附件 → 清 dirty。
- 提醒：`remind_at` 变更（本地或同步而来）都会重新调度精确闹钟；开机后 RebootReceiver 补调度；通知渠道单独建"提醒"渠道并引导授权（家庭场景提醒可靠性优先级最高）。

### 8.4 关键交互细节

- 编辑页**自动保存**：停顿 2 秒防抖入库 + 触发同步，无"保存"按钮。
- 列表卡片**长按多选**：批量置顶/归档/删除/改颜色。
- 清单条目**左右滑动**完成/删除，已勾选条目自动沉底。
- 空状态：插画 + "记下第一条家庭备忘吧"。
- 同步状态显性化：首页顶部细条"同步中… / 已同步 12:30 / 离线，更改已保存本地"。
- 冲突提示：通知栏 + 卡片角标"发现冲突副本"，点开二选一。

## 9. 安全设计

- 密码 argon2id 哈希存储；登录换长期 token，管理端可见设备列表、可踢下线。
- 局域网 HTTP + token 可接受；出外网一律走 Tailscale 加密隧道或 HTTPS 反代。
- 无任何第三方统计/推送 SDK，通知提醒全部本地调度（也避免了国内 ROM 推送通道的碎片问题）。
- 每日自动备份 + 管理页一键全量导出（JSON + 附件 zip），家庭数据永远有底。

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| FPK 规范细节与预期不符 | 以飞牛开发者平台官方文档为准；兜底方案：Docker Compose 版（fnOS 原生支持 Docker），打包可后置到 M4 |
| 外网不可达 | 主推 Tailscale 组网；客户端离线优先保证任何网络状况下可用 |
| 家人时钟漂移影响 LWW | 以服务端接收顺序定胜负，内容本身仍以后写者为准；冲突副本兜底 |
| 国内 ROM 杀后台导致同步/提醒失效 | WorkManager + 精确闹钟 + 引导加白名单（设置页内置各家 ROM 设置引导） |
| 数据误删 | 软删除 + 回收站 30 天 + 每日备份 + 全量导出 |
